### ***Partial Ordering Rules***

Birdern fazla *Function Template*'in oldugu bazi durumlarda bir fonksiyon cagrisi, birden fazla *Function Template*'e uygun dusebilir. Bu durumda uygulanan kural *Partial Ordering*.

Burada amac Function Overload Resolution'i saglamak ve eger secilebilirse templatelerden birini overload resolution ile secmek. Aksi durumda ambiguity ile sonuclanabilir.

> Eger birden fazla template viable ise, en specialized olani secilecek.

```cpp
#include <iostream>

template<typename T>
void f(T*)
{
    std::cout << "T*\n";
}

template<typename T>
void f(T**)
{
    std::cout << "T**\n";
}

int main()
{
    int* p{};
    f(&p);
}

/* 
    Out:
    T**
*/
```

Yukaridaki kod soz konusu oldugunda her iki template'te tek basina dusunuldugunde viable.

```cpp
#include <iostream>

template<class T>
void f(T)
{
    std::cout << "T\n";
}

template<typename T>
void f(T const*)
{
    std::cout << "T const*\n";
}


int main()
{
    const int* p = nullptr;
    f(p);
}

/* 
    Out:
    T const*
*/
```
*Partial **Ordering*** denmesinin sebebi, Overload Resolution'da bir siralamaya tabi tutulmasi. Siralama yapilabiliyorsa; biri digerinden daha iyi demek. Yapilamiyorsa; unordered demek.

Standardin tanimi:
Bir tur oldugunu dusunun (Orn: `Myclass`). Bu turden bir degeri fonksiyonlardan birine gonderdiginizde `T` yerine olusacak turden bir arguman gondererek diger fonksiyonu cagirirsaniz ve sentaks hatasi olmazsa; sentaks hatasi olmayan secilir.

```cpp

{
    std::cout << "T\n";
}

template<class T>
void g(T&)
{
    std::cout << "T&\n";
}


int main()
{
    int i = 0;
    g(i); // Ambiguity.
}
```

	return os << t;		// no separator after the last element in the pack
