### Deduction Guides

Arka planda CTAD'la birlikte, dilin bir baska araci olan *Deduction Guides* calisir.

Derleyici dilin kurallarina gore bir class template'teki ctor'a bagli olarak ozel bir sentaks ile bir Deduction Guide olusturuyor. Eger derleyicinin olusturdugu Deduction Guide kullaniliyorsa buna; *Implicit Deduction Guide* deniyor. Programcinin yazdigina ise *User Defined Deduction Guide* denir.

```cpp
template<typename T>
class Myclass {
public:
    Myclass(T);
};

// User Defined Deduction Guide
template<typename T>
Myclass(T) -> Myclass<T>;
```

Kullanici bir Deduction Guide olusturmazsa, derleyici ctor'a bakarak yukaridaki gibi bir deduction guide'i implicitly olusturuyor.

Anlami, `Myclass`'in ctor'ina `T` turunden bir deger gonderilirse template argumani `T` olsun ve `Myclass<T>` acilimi kullanilsin. Fakat bu derleyicinin otomatik olarak verdigi deduction guide.

Kendimiz bir deduction guide olusturursak cikarim bizim olusturdugumuz deduction guide'a gore yapilir. STL'de de bircok yerde bu yontem kullaniliyor.

```cpp
template<typename T>
class Myclass {
public:
    Myclass(T);
};

// User Defined Deduction Guide
Myclass(int) -> Myclass<double>;

int main()
{
    Myclass m = 10; // Myclass<double>
}
```

## CONCEPTS ~ *Since C++20*

Conceptler C++20 kutuphanesi ile eklenen `<ranges>` kutuphanesi ile dogrudan ilgili.

C++'in generic programming tarafinda problematik durumlardan biri template'lerin constraint edilmesi.

Bunun yerine:
- `static_assert` kullanabiliriz. Fakat o zaman, interface'in bir bileseni olmaz.
- SFINAE teknikleri kullanilabilir. Hem karmasik, hem uzmanlik gerektiriyor, ayrica butun template kategorileri ile kullanilamiyor.

Concept'lerin dile eklenmesindeki temel amaclar:
- Template kod olusturmayi cok kolay hale getirir.
- Template'leri constraint etmeyi daha anlasilir kolay bir sentaksla mumkun kiliyor.
- SFINAE'de oldugu gibi, compile time kod seciminde de kullanilabilir.

Aslinda Concept yeni bir template kategorisi. Constraint'lerin isimlendirilmis bicimi.

SFINAE'e gore en onemli farki; sadece function ve class templateleri degil, diger template'leri de constraint etmek icin kullanilabiliyor.

```cpp
#include <concepts>

template<std::integral T>
class Myclass {

};

int main()
{
    Myclass<int> x;
    // Myclass<double> y; // Invalid.
}
```

Abbreviated Template Syntax ile de kullanilabiliyor:

```cpp
#include <concepts>

void foo(std::integral auto x)
{

}

int main()
{
    foo(12);
    // foo(1.2); // Invalid.
}
```

Dile eklenen, yalnizca `concept` anahtar sozcugu ve yeni template kategorisi degil. Beraberinde eklenen 2 sentaks ogesi daha var. Bunlar; conceptlerden bagimsiz ya da birlikte kullanilabiliyor:
- Requires Expression
- Requires Clause

### Bir Template'in Constraint Edilmesi

#### Requires Clause

`requires` keywordunun yanina `bool` turden bir sabit ifadesi yazilir.

```cpp
requires (sizeof(int) > 2)
```

Function template soz konusu oldugunda; 
- Fonksiyonun geri donus degeri turunden once,
- Fonksiyonun parametre parantezinin kapanmasinda sonra yazilabilir. (*Trailing Requires Clause*)

```cpp
#include <concepts>

template<typename T>
requires (sizeof(T) > 2)
void foo(T x)
{

}

template<typename T>
void bar(T x) requires (sizeof(T) > 2)
{

}
```

*Trailing Requires Clause* sentaksinda fonksiyon parametre degiskeni kullanilabilir. Fakat obur sentaksta parametre degiskeni scope disinda kalir.

Requires Clause'ta `requires` keywordunu izleyen ogeler sunlar olabilir:
- Compile time ifadesi. (*Ad-hoc boolean expression*)
- Bir conceptin kendisi.
- Requires expression

Ayrica bu ogeleri `&&` operatoru ile birbirine baglayabiliriz.


```cpp
#include <concepts>

template<typename T>
requires std::integral<T>
void foo(T x)
{

}
```

```cpp
#include <concepts>
#include <iterator>

template<typename T>
requires (sizeof(T) > 2) && std::input_iterator<T>
void foo(T x)
{

}
```

```cpp
#include <concepts>
#include <iterator>

template<typename T>
requires (sizeof(T) > 2) && std::input_iterator<T>
&& requires{typename T::value_type;}
void foo(T x)
{

}
```

```cpp
#include <concepts>
#include <iterator>
#include <type_traits>

template<typename T, typename U>
requires std::convertible_to<T, U>
auto foo(T x, U y)
{
    return x + y;
}

int main()
{
    foo(12, 5.6);
}
```

Requires Clause'ta eger dogrudan compile time sabit ifadesi kullanilacaksa o zaman parantez icine alinmasi gerekiyor. Fakat Requires Clause'ta kullanilan bir concept ise o zaman parantez icine alinamsina gerek yok.

```cpp
#include <concepts>
#include <iterator>
#include <type_traits>

template<typename T, typename U>
requires std::integral<T> && std::floating_point<U>
auto foo(T x, U y)
{
    return x + y;
}

int main()
{
    foo(12, 5.6);
    // foo(1.2, 10); // Invalid.
}
```

[Hocanin notlari.](https://github.com/necatiergin/CONCEPTS/blob/3defa2eab1c11bfda5deab00919fd323c68b7b08/notlar.md)

#### Requires Expression

Adi ustunde bir ifade. Oyle bir ifadeki compile time'da boolean bir deger uretiyor.

- Bir derleme zamani(sabit) ifadesi. Sabit ifadesi gereken herhangi bir yerde kullanilabilir!

Sentaks:

- `requires` keyword kullanilir.
- Opsiyonel olarak, template parametresine bagli parametre/ler kullanilabilir.
- Kume parametresi icinde farkli sinamalara iliskin constraintler yazilir. 

```cpp
requires(T& x, T y) {

}
```

Requires expression'in ici bos olamaz.

Requires Expression'in 4 farkli ogesi olabilir:
1. Simple Requirement: Bir ifadenin gecerliliginin sinanmasi.
2. ???

Simple Requirement: Oyle bir ifade ki `;` ile sonlanacak ve o ifade gecerli bir ifade olmak zorunda.

```cpp
#include <concepts>
#include <iterator>
#include <type_traits>

template<typename T>
requires requires(T x) {
            x + x;
        }
class Myclass {

};

int main()
{
    Myclass<int> x;
    // Myclass<int*> y; // Invalid.
}
```

```cpp
template<typename T>
requires requires(T x) {
            x - x;
        }
class Myclass {

};

int main()
{
    Myclass<int> x;
    Myclass<int*> y;
}
```
